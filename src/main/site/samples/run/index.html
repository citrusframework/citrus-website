Running the samples

How to

Code repository

The Citrus samples are available at GitHub in several repositories. You can navigate to these repositories and use git to clone the code to your local machine. After that you can build and execute the samples on your local machine.

  • citrus-samples
  • citrus-quarkus-examples
  • citrus-camel-eip-examples
  • citrus-camel-jbang-demo
  • camel-jbang-examples

Build

The sample application uses Maven as build tool. So you can compile, package and test the sample projects with.

This executes the complete Maven build lifecycle. The Maven build usually starts the system under test automatically, so you do not have to worry about proper configuration of endpoints and URLs. Sometimes you may need to explicitly add a property `embedded` in order to enable the automatic provisioning of the application under test.

The embedded option automatically starts the application under test before the integration test phase takes place.

The Maven build automatically runs all Citrus test cases in the project. During the build execution you will see Citrus performing the integration tests and printing log messages. When the tests are done the embedded sample application under test is automatically stopped and the Maven test results with successful and failed tests are presented to you.

Sample applications

The samples in Citrus represent small applications that are started as a system under test. Usually the sample application is a web application implemented in one of the runtimes Quarkus, Spring Boot and Apache Camel. All runtimes act in the same way. You can start the applications on your local machine as part of the test run.

No matter what sample application is used Citrus interacts with the applications as part of the integration tests in order to trigger certain business logic and to verify its outcome.

Embedding the system under test into the Maven build lifecycle so the application is run and stopped automatically is a good approach when running automated tests in a continuous build.

In some other cases you may want to start the sample application manually before the tests so the application is still alive when the tests and the Maven build is finished.
